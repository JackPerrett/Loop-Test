# UX/UI Auditor

A CLI tool that crawls a website with a real browser (Playwright/Chromium),
audits every page it finds against common UX and UI norms, and generates a
Mad River–branded PDF (plus a Markdown report) covering the whole site.

## What it checks

| Category | Examples | Reference norms |
|---|---|---|
| **Accessibility** | Color contrast, alt text, ARIA, form labels, landmarks, heading order | WCAG 2.1 A/AA (via [axe-core](https://github.com/dequelabs/axe-core)) |
| **Responsive Design** | Viewport meta tag, horizontal overflow at mobile/tablet/desktop widths, touch target size, mobile font size | WCAG 2.5.5, Google Mobile-Friendly guidelines |
| **Performance** | Load time, time-to-first-byte, request count, page weight | Core Web Vitals / web performance best practice |
| **Content & Structure** | Title/meta description, favicon, `lang` attribute, heading hierarchy, vague link text, broken images, nav landmark, unsafe `target="_blank"` links, console/JS errors | Nielsen's usability heuristics, SEO best practice |

Each finding is tagged with a severity (Critical/High/Medium/Low), the
specific norm it violates, and is footnoted to an authoritative source
(a WCAG success criterion, a Nielsen Norman Group article, web.dev, MDN,
OWASP, etc.) explaining *why* it matters — suitable for handing to a design
or engineering team, or a client, as a citable action list.

## Usage

```bash
npm install
node src/cli.js <url> [options]
```

By default the tool **crawls the site** (same-origin only) starting from
`<url>`, following links up to `--max-depth` link-hops and `--max-pages`
pages, and audits every page it finds.

Options:

- `-o, --output <dir>` — output directory for the report + screenshots (default: `./audit-output`)
- `-t, --timeout <ms>` — page load timeout per page (default: `30000`)
- `--max-pages <n>` — maximum number of pages to crawl (default: `15`)
- `--max-depth <n>` — maximum link depth from the start URL (default: `3`)
- `--single-page` — audit only the given URL, no crawling
- `--no-pdf` — skip generating the branded PDF (Markdown is always written)

Examples:

```bash
node src/cli.js https://example.com --output ./reports/example
node src/cli.js https://example.com --single-page
node src/cli.js https://example.com --max-pages 40 --max-depth 4
```

This produces:

```
reports/example/
  example-com-ux-ui-audit.md      # aggregated Markdown report, all pages
  example-com-ux-ui-audit.pdf     # the same audit as a designed, citable PDF
  screenshots/
    example-com-p1-mobile.png     # homepage only, 3 viewports
    example-com-p1-tablet.png
    example-com-p1-desktop.png
```

### Report contents

- Cover page with the site-wide score (0–100), letter grade, and a
  per-category breakdown, averaged across every page crawled
- Executive summary: category scorecard, a table of every page crawled with
  its own score, site-wide priority recommendations, homepage viewports
- A findings section per crawled page — each issue is a severity-striped
  card with its description, the norm it violates, a code sample where
  relevant, and footnote markers linking to source citations
- A numbered **References** page listing every distinct source cited across
  the whole site, with live links (WCAG success criteria, Nielsen Norman
  Group, web.dev, MDN, WebAIM, Google Search Central, OWASP)

The PDF is generated by rendering a dedicated HTML report
(`src/report/generateHtmlReport.js`) with Chromium (`page.pdf()`) — no extra
system dependencies (e.g. wkhtmltopdf/pandoc) required beyond Playwright.

## Brand system

The PDF follows Mad River Ltd's creative template (`MR_Creative_Template_Final.pdf`):

- **Type** — 'Spock Striked' for the cover's display title, 'DIN Next LT Pro
  Bold Condensed' for page titles, eyebrow labels, footers and numbered
  markers (both embedded as base64 `@font-face` so no system install is
  needed), and a neutral body sans for descriptions.
- **Colour** — black/white base with the brand's khaki green as the single
  accent (score rings, category bars, citation marks, priority markers).
  Severity colour-coding (Critical/High/Medium/Low) is kept deliberately
  separate from the khaki brand accent.
- **Layout** — a dark full-bleed cover mirrors the guide's breaker-page
  treatment; the executive summary and findings pages reuse the guide's
  label-and-hairline-rule "spec sheet" layout; priority recommendations use
  the guide's numbered-marker-plus-connector-line device (in place of the
  guide's "MR Recommends" tag); the footer follows the guide's
  `CLIENT NAME / PROJECT-VER / page number` format; the back page mirrors
  the guide's colophon (centered wordmark, small print).
- **Logo** — the literal keyline "MAD RIVER" lockup, rasterised from the
  supplied vector at high resolution. It's black line-art on a transparent
  ground (a true keyline mark, drawn for light surfaces), so on the dark
  cover/colophon pages it sits on a small white card rather than being
  redrawn.

Brand assets live in `src/report/brand/` (`DINNextLTProBoldCondensed.otf`,
`SpockStrikedRegular.otf`, `mad-river-wordmark.png`) and are loaded via
`src/report/brandAssets.js`. **Note:** the two fonts are commercial/licensed
typefaces — they're included here because they were supplied for this
deliverable; check your license terms before redistributing this repo
further. The exact "MR Khaki green" hex wasn't specified anywhere in the
supplied guide, so `--khaki: #6B6A45` in `generateHtmlReport.js` is a
considered approximation — swap it for the real brand hex if you have it.

## As a library

```js
import { auditSite } from './src/audit.js';

const { reportPath, pdfPath, siteScorecard, pages } = await auditSite('https://example.com', {
  outputDir: './out',
  maxPages: 20,
  maxDepth: 3,
});
```

## Scope and limitations

- Crawling is same-origin only and skips non-page assets (images, PDFs,
  stylesheets, etc). It follows `<a href>` links found in the rendered DOM —
  pages only reachable via JS-driven navigation (not real anchors) won't be
  discovered.
- Full-viewport screenshots are only captured for the start page, to keep
  runtime and PDF size reasonable on larger crawls.
- Automated checks catch a meaningful, well-established subset of UX/UI
  problems but are not a substitute for manual usability testing with real
  users, nor for a full manual WCAG audit.
- Pages requiring authentication or complex interaction flows before the
  content of interest is visible are not currently supported out of the box.

## Trying it out

`examples/` contains:
- `sample-site.html` / `good-site.html` — single-page fixtures (flawed vs.
  clean) for `--single-page` testing.
- `site/` — a small 4-page linked fixture (`index.html`, `products.html`,
  `about.html`, `contact.html`) for exercising the crawler.

```bash
npx http-server examples/site -p 8080 &
node src/cli.js http://localhost:8080/index.html
```
